# HERO-001 — Доработать hero-анимацию с предзагрузкой слоёв

## Статус

Готова к локальной проверке.

## Контекст

Текущая реализация занавеса на главной странице концептуально верная, но технически должна быть переработана. Сейчас идея работает как прототип, но нужна более правильная многослойная hero-анимация с предзагрузкой графики.

## Цель

Сделать hero-сцену на главной странице как многослойную анимацию с обязательной предзагрузкой всех графических ассетов перед стартом анимации.

## Текущая точка входа

- Локальный сайт: `http://127.0.0.1:8767/`
- Ветка: `chore/unified-local-workspace`
- Тема: `wp-content/themes/absurd-stage-v1`
- Основная разметка hero: `wp-content/themes/absurd-stage-v1/front-page.php`
- Основные стили hero/curtain: `wp-content/themes/absurd-stage-v1/style.css`

## Что нужно изменить

1. Разделить hero на независимые графические слои:
   - левый занавес;
   - правый занавес;
   - сцена за занавесом.
2. Добавить предзагрузку всех hero-ассетов до запуска анимации:
   - анимация не должна стартовать, пока не загружены сцена и все кадры/слои занавеса;
   - до готовности можно показывать статичный fallback/loader без дёргания layout.
3. Заменить текущую hero-картинку сцены на новую версию без занавеса.
4. Для сцены за занавесом сохранить текущую идею медленного приближения/zoom-in.
5. Занавес сделать реалистичнее:
   - рассмотреть PNG sequence или sprite sheet;
   - по мере открытия занавеса должен меняться фон/кадр, чтобы ткань выглядела живой, а не просто как статичная маска;
   - левый и правый занавес должны двигаться синхронно, но могут иметь отдельные кадры.
6. Сохранить поддержку `prefers-reduced-motion`:
   - при reduced motion не запускать активную анимацию;
   - показать корректное статичное состояние hero.
7. Не добавлять тяжёлые зависимости без необходимости.

## Возможная реализация

- Добавить небольшой JS-модуль в тему для preload hero-ассетов и переключения класса вроде `hero-ready`.
- Для занавеса выбрать один из вариантов:
  - sprite sheet + CSS `steps()`;
  - набор PNG-кадров + JS/CSS смена `background-position`/`background-image`;
  - CSS-анимация движения контейнеров + покадровая смена текстуры ткани.
- Сцена остаётся отдельным background/image-слоем с медленным `transform: scale(...)`.

## Критерии готовности

- При первом открытии главной нет «мигания» и старта анимации до загрузки hero-графики.
- Занавес выглядит как анимированная ткань, а не как статичная картинка, сдвинутая в стороны.
- Сцена за занавесом плавно приближается.
- Мобильный вид не ломается.
- `prefers-reduced-motion` работает корректно.
- Главная страница отвечает `200` на `http://127.0.0.1:8767/`.

## Ограничения

- Работать только с кастомной темой/плагином в репозитории.
- Не трогать WordPress core, uploads, БД, DNS, GitHub Secrets и `main` без отдельного явного разрешения.
- Не пушить и не деплоить без подтверждения.

## Заметки по реализации

- Hero переработан на независимые слои: сцена, левый занавес, правый занавес и лёгкий loader до готовности графики.
- Добавлен JS-preload hero-ассетов: выбранные desktop/mobile изображения сцены и занавеса загружаются до старта анимации, после чего ставится класс `is-ready`.
- Сцена сохраняет медленный zoom-in, занавес открывается двумя синхронными слоями с покадровым `steps()`-сдвигом текстуры ткани.
- `prefers-reduced-motion` переводит hero в статичное состояние без активного открытия занавеса и loader.
- Ограничение: отдельного ассета сцены без занавеса пока нет, поэтому текущие `curtain-desktop.webp` и `curtain-mobile.webp` временно используются и как сцена-прототип. Для финального визуала нужен отдельный scene-ассет без занавеса.

## Подсказка для следующего чата

Начать с проверки `git status --short --branch`, затем открыть главную локально и изучить текущие файлы `front-page.php` и `style.css`. Новые ассеты занавеса/сцены, если их ещё нет, нужно запросить или временно подготовить как прототипные файлы в теме.
