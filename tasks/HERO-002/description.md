# HERO-002 — видео-first раскрытие занавеса, безопасный fallback

**Статус:** `code_ready_for_local_visual_review` — НЕ `E2E PASS`, НЕ художественно утверждённый ролик.

**Источник:** владелец сообщил, что локальный Codex начал переход от CSS/JS sprite-анимации к двум сгенерированным PixVerse MP4. Переданный GitHub commit содержит оба видео, кадры `hero-start16x9.png` и `hero16x9.png`, но **в текущей ветке `chore/unified-local-workspace` видео ещё не подключено в HTML/JS**. Это отдельный PR поверх указанной ветки, чтобы сохранить её и иметь возможность сравнения с прежним эффектом.

## Реализовано в этой feature-ветке

- `front-page.php`: декоративный `<video muted playsinline preload="none">` без loop, отдельные исходный и финальный кадры. Название `АБСУРД`, `Афиша`, Telegram остаются реальными HTML-элементами, не частью видеокадра.
- В качестве **предварительного** кандидата включён `assets/images/PixVerse_V6_Image_Text_540P_Heavy_burgundy_vel.mp4`. Альтернатива уже лежит рядом: `PixVerse_V6_Transition_540P_The_camera_slowly_.mp4`. Менять источник в `$hero_video` (PHP) для честного локального A/B. Никто ещё не проверил, какое видео действительно **раскрывает**, а не **закрывает** занавес и не содержит швов.
- `style.css`: статичная стартовая картинка при загрузке; после успешного autoplay включается видео; при ошибке — финальная статичная сцена; после `ended` сохраняется последний кадр видео, без бесконечного зацикливания. Убрана прежняя подмена «ткани» двух сдвигающихся прямоугольников.
- `site.js`: видео загружается **только на desktop**, без скачивания MP4 на mobile (ширина 800 px и менее); также не загружается при `prefers-reduced-motion: reduce`, `Save-Data`, в неактивной вкладке. При отсутствии поддержки MP4, ошибке загрузки, запрете autoplay или таймауте 5.5 с — открытая статичная сцена без ожидания, страницы и CTA доступны. Пауза/возобновление при смене видимости вкладки.
- CSS и изображение первого кадра предотвращают появление финальной сцены на долю секунды **до** начала видео. Никаких библиотек и таймеров для скролл-захвата.

## Почему это только кандидат для реального просмотра

1. Названия PixVerse файлов содержат **540P** — разрешение, вероятно, недостаточно для большого desktop hero. Нужно проверить размеры, bitrate, fps, duration, реальные compression artifacts, мобильную обрезку, качество складок и совпадение начального/конечного кадра. Эти характеристики **пока не проверены**.
2. **Нельзя считать видео красивым и правильным** без просмотра или кадрового монтажа: направление движения занавеса может быть ошибочным; видео может содержать текст, которого не должно быть.
3. Неподготовленное 16:9 видео показываем только на desktop; на мобильных пока качественный статичный fallback из принятого мокапа `curtain-mobile.webp`. После подтверждения эффекта нужно решить, генерировать ли отдельный portrait-вариант.
4. Слои источника сейчас намеренно **не используются как реальные alpha-текстуры**. Видео — честная кино-вставка; не заявлять, что оно динамическая настоящая 3D сцена.
5. Текущие CSS/HTML обновлены непосредственно в приватной **feature-ветке**, но WordPress на Dmitanium **ещё не подтянул эти изменения**. Локальный localhost недоступен исполнителю через GitHub; browser/E2E PASS нельзя утверждать.

3. Открыть `http://127.0.0.1:8767/` в Chrome с disable cache. Отснять **первый кадр**, 0.7 s, 1.5 s, конец; оценить естественность раскрытия, композицию, цвет и плавность (нет reverse curtain closing / jitter / flashes).
4. Сравнить два video-файла по качеству/движению на одинаковом URL; выбрать лучший либо вернуть на генерацию. В процессе просмотра контролировать отсутствие встроенных надписей / дублей DOM H1.

6. Если видео действительно подходит: независимый `e2e_` Chat High → **PASS/FAIL**, исправить блокеры. Только тогда поднимать вопрос о принятии нового hero; если нет — использовать прежний локальный вариант и повторить генерацию.
7. Сохранять `a2ice/absurd` GitHub публичным **только для материалов с разрешёнными правами**. Исходники PixVerse уже запушены владельцем, не добавлять другие клиентские материалы без проверки. Не делать внешнего deploy и не мержить в `main` до визуальной проверки и согласования.
